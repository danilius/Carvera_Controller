# CYD Pendant Tool Change Confirmation System

## Overview

The CYD pendant now supports bidirectional communication for manual tool change operations. When the firmware requires a manual tool clamp/unclamp, the controller:

1. Detects the firmware message in the MDI stream
2. Sends a notification to the ESP32 via TCP
3. Waits for user confirmation from the ESP32
4. Resumes machine operation when confirmed

## Message Flow

### 1. Firmware → Controller (MDI Stream)

The firmware sends pause messages before tool clamp/unclamp operations:

**Drop Tool (Unclamp):**
```
;Ready to drop tool 7. Prepare to catch tool, resume will loosen collet
```

**Pick Tool (Clamp):**
```
;Ready to install tool 8. Resume will tighten the collet
```

These messages are generated by:
- `ATCHandler::fill_manual_drop_scripts()` at line 588
- `ATCHandler::fill_manual_pickup_scripts()` at line 623

The machine pauses via M600.5 command after these messages.

### 2. Controller → ESP32 (Tool Action Required)

When detected, the controller sends JSON to ESP32:

```json
{
  "type": "tool_action_required",
  "action": "clamp",
  "tool": 8,
  "message": ";Ready to install tool 8. Resume will tighten the collet"
}
```

or

```json
{
  "type": "tool_action_required",
  "action": "unclamp",
  "tool": 7,
  "message": ";Ready to drop tool 7. Prepare to catch tool, resume will loosen collet"
}
```

### 3. ESP32 → Controller (Confirmation)

After the user presses a button on the ESP32 display, send:

```json
{
  "type": "tool_action_confirm",
  "action": "clamp"
}
```

or

```json
{
  "type": "tool_action_confirm",
  "action": "unclamp"
}
```

The controller will then call `controller.resume()` to resume the machine.

## Code Changes

### 1. Message Detection ([main.py](carveracontroller/main.py) lines 3035-3049)

Added regex-based detection of firmware messages in the MDI handler:

```python
# Check for manual tool change messages and notify CYD pendant if enabled
if self.pendant is not None and hasattr(self.pendant, 'notify_tool_action'):
    import re
    # Detect "Ready to drop tool N. Prepare to catch tool, resume will loosen collet"
    drop_match = re.search(r'Ready to drop tool (\d+).*resume will loosen collet', line, re.IGNORECASE)
    if drop_match:
        tool_num = int(drop_match.group(1))
        self.pendant.notify_tool_action('unclamp', tool_num, line.strip())
    
    # Detect "Ready to install tool N. Resume will tighten the collet"
    pickup_match = re.search(r'Ready to install tool (\d+).*resume will tighten', line, re.IGNORECASE)
    if pickup_match:
        tool_num = int(pickup_match.group(1))
        self.pendant.notify_tool_action('clamp', tool_num, line.strip())
```

### 2. CYD Pendant Notification ([pendant.py](carveracontroller/addons/pendant/pendant.py))

Added `notify_tool_action()` method:

```python
def notify_tool_action(self, action: str, tool: int, message: str) -> None:
    """
    Called by main.py when a manual tool change message is detected.
    Sends notification to ESP32 and tracks pending action.
    """
    # Avoid duplicate notifications for the same action/tool
    if self._pending_tool_action == {"action": action, "tool": tool}:
        return

    self._pending_tool_action = {"action": action, "tool": tool}
    
    payload = {
        "type": "tool_action_required",
        "action": action,
        "tool": tool,
        "message": message,
    }
    self._client.send_json(payload)
```

### 3. Confirmation Handler ([pendant.py](carveracontroller/addons/pendant/pendant.py))

Updated `_handle_incoming()` to process confirmations:

```python
def _handle_incoming(self, _client: cyd.TCPClient, msg: dict) -> None:
    """
    Handle incoming messages from ESP32.
    Looks for tool_action_confirm to resume machine operation.
    """
    msg_type = msg.get("type")
    
    if msg_type == "tool_action_confirm":
        action = msg.get("action")
        
        # Verify this matches our pending action
        if self._pending_tool_action and self._pending_tool_action["action"] == action:
            # Clear pending state
            self._pending_tool_action = None
            
            # Send resume command to continue machine operation
            if self._controller:
                self._controller.play()
```

## Testing

### 1. Start the Test Server

In one terminal:

```bash
poetry run python scripts/cyd_echo_server.py
```

### 2. Configure Controller

In the Carvera Controller settings:
- Set **CYD Pendant Host** to `127.0.0.1`
- Set **CYD Pendant Port** to `9876`
- Select **CYD** as the pendant type

### 3. Trigger Manual Tool Change

In the MDI or via gcode file, execute a manual tool change:

```gcode
M6T7
```

This will trigger a manual tool change for tool 7 (tools > 6 use manual change).

### 4. Observe the Flow

1. **Controller MDI** will show: `;Ready to install tool 7. Resume will tighten the collet`
2. **Test Server** will print:
   ```
   TOOL ACTION REQUIRED:
     Action: clamp
     Tool: 7
     Message: ;Ready to install tool 7. Resume will tighten the collet
   ============================================================
   Simulating ESP32 display: [ CLAMP TOOL 7 ]
   Press Enter to send confirmation back to controller...
   ```
3. **Press Enter** in the test server terminal
4. **Test Server** sends confirmation and prints: `Machine should resume now!`
5. **Controller** resumes operation and executes M490.1 (clamp command)

### 5. Full Manual Tool Change Test

Use the test gcode file:

```gcode
M6T7    ; Pick up tool 7 (manual)
G0 X10 Y10 Z5  ; Move somewhere
M6T8    ; Change to tool 8 (manual)
M6T-1   ; Drop tool (manual)
```

You should see 3 confirmations:
1. Clamp for tool 7
2. Unclamp for tool 7 / Clamp for tool 8
3. Unclamp to drop tool

## ESP32 Implementation Notes

Your ESP32 firmware should:

1. **Display the notification** when receiving `tool_action_required`:
   - Show the action type (CLAMP or UNCLAMP)
   - Show the tool number
   - Show a confirmation button

2. **Send confirmation** when button is pressed:
   - Must match the action type from the request
   - Use exact JSON format shown above

3. **Handle connection lifecycle**:
   - Maintain persistent TCP connection to controller
   - Reconnect if connection drops
   - Send/receive newline-delimited JSON

## Duplicate Prevention

The system prevents duplicate notifications using `_pending_tool_action` state:
- Only one notification per action/tool combination
- Cleared when confirmation is received
- Cleared on next different action

## Troubleshooting

### Controller doesn't send notifications

Check:
1. CYD pendant is selected in settings
2. Host/port are configured correctly
3. TCP connection is established (check console logs)

### ESP32 doesn't receive messages

Check:
1. Network connectivity
2. Firewall rules
3. JSON parsing (must handle newline delimiter)

### Machine doesn't resume after confirmation

Check:
1. Confirmation message format is exact
2. Action matches the request ("clamp" or "unclamp")
3. Controller logs show "Sent resume command"
